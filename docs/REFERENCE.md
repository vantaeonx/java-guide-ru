# Памятки после первого прохода

## Выбор структуры

| Нужно | Подход |
|---|---|
| Фиксированное число однотипных элементов | Массив |
| Последовательность с добавлением и повторами | ArrayList через List |
| Уникальность без порядка | HashSet |
| Уникальность с порядком первого появления | LinkedHashSet |
| Поиск значения по ключу | Map |
| Отчёт по ключам в порядке регистрации | LinkedHashMap |
| Сортированный порядок ключей | TreeMap с осмысленным сравнением |
| Закрытый набор состояний | enum |
| Неизменяемое по компонентам значение | record с проверкой и защитой ссылочных компонентов |
| Изменяемый объект с правилами | Класс с private-полями и операциями |

## Прежде чем запускать

Проверь типы промежуточных выражений, границы индексов, причины остановки цикла,
допустимость null и пустоты. Если операция меняет состояние, проверь отказ до записи.
Если работаешь с файлом, уточни рабочую папку, UTF-8, режим перезаписи и закрытие ресурса.

## Разбор проблемы

1. Зафиксируй точный вход, ожидаемое и полученное поведение.
2. Найди первый момент расхождения, а не последнюю видимую ошибку.
3. Уменьши вход. Нарисуй ссылки или таблицу итераций.
4. Проверь одну гипотезу одним изменением.
5. После исправления оставь проверку прежнего дефекта.

## Минимальная матрица проверок

| Вид операции | Проверки |
|---|---|
| Диапазон | Ниже, ровно нижняя, внутри, ровно верхняя, выше |
| Последовательность | Пустая, один элемент, несколько, повторы |
| Максимум | Все отрицательные, один, пустота по договору |
| Строка | Пустая, пробельная, разделитель отсутствует, пустое поле |
| Объект | Корректное создание, отказ создания, успех изменения, отказ без изменения |
| Map | Новый ключ, повторный ключ, отсутствующий, равный новый ключ |
| Файл | Отсутствует, пустой, русские данные, повреждённая строка, повторный запуск |
| Сохранение | Успех, ошибка подготовки, ошибка замены, старые данные после отказа |

## Отсылка к следующим темам

После этого курса отдельно изучай Maven/Gradle и зависимости, JUnit, логирование,
Git, сетевые протоколы и базы данных. Многопоточность требует отдельной модели памяти
и синхронизации. Для Minecraft сначала выбери версию игры и загрузчик, проверь их
официальные требования к JDK и создай минимальное наблюдаемое поведение.
