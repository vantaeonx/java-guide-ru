# Мини-проект 04. Каталог мастерской

После главы 16. Объектная модель, Map/Set, уникальные ключи и история операций.

## Договор приложения

Создай Item с final id,name и private nonnegative int stock. Id/name непустые после trim, id не меняется. Catalog хранит LinkedHashMap<String,Item>. Register запрещает повтор id, increase(id,n) и take(id,n) требуют n>=0, take не превышает stock; неизвестный id -> IllegalArgumentException. Увеличение, выходящее за int, запрещено до изменения. History - List<String> только успешных операций с точным форматом REGISTER:id, INCREASE:id:n, TAKE:id:n. List выдаётся неизменяемой копией. LowStock(limit) возвращает id с stock<=limit в порядке регистрации, limit>=0. Main работает с фиксированными операциями и проверками, без чтения файла.

## Исходные данные

```java
String[] ids = {"iron", "wood"};
String[] names = {"Железо", "Доски"};
int[] stocks = {5, 2};
```

## Этапы

1. Разработай Item с контролем остатка и переполнения.
2. Добавь Catalog и уникальность идентификатора.
3. Записывай историю только после успешной операции.
4. Проверь lowStock и невозможность изменить выданный список истории.

## Критерии готовности

- После REGISTER iron=5, wood=2 и TAKE iron:3 lowStock(2) -> [iron,wood].
- TAKE wood:3 отвергнут: wood=2, история не выросла.
- Повтор REGISTER iron отвергнут, исходная запись не заменена.
- INCREASE на Integer.MAX_VALUE при ненулевом остатке отвергнут без переполнения.
