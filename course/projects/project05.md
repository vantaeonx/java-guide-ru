# Мини-проект 05. Файловый журнал расходов

После главы 18. Текстовый формат, разбор, ошибки и проверяемый финансовый расчёт в центах.

## Договор приложения

Работай только в build/sandbox/project05. Создай входной UTF-8 файл expenses.txt из initialLines для демонстрации. Формат category;cents: category непустая, без краевых пробелов и без ;, cents целое long 0..1000000000. Ровно два поля. Прочитай все строки, собирай Map<String,Long> сумм в порядке первого появления; неверные строки пропускай с ERROR:номер:причина, пустая строка ошибочна. Номер с 1. Если суммарное сложение переполняется, откажись от отчёта явно, не допускай обёрнутого результата. Сохрани report.txt: по строке category;sum, затем TOTAL;sum. TOTAL запрещена как категория. IOException не маскируй ошибкой формата. Раздели parse, aggregate и file adapter.

## Исходные данные

```java
List<String> initialLines = List.of("food;125", "travel;300", "food;75", "bad", "food;-1");
```

## Этапы

1. Запиши точный формат и выбери тип результата разбора записи.
2. Проверь парсер в памяти до файловых операций.
3. Реализуй агрегирование допустимых строк и отдельный список ошибок.
4. Добавь запись отчёта и пользовательское сообщение об IOException.

## Критерии готовности

- Пример: ошибки строк 4,5; report food;200, travel;300, TOTAL;500.
- Пустой файл -> только TOTAL;0; файл с одними ошибками также TOTAL;0 и полный отчёт об ошибках.
- Русская category сохраняется; отсутствие входного файла при режиме чтения даёт файловую ошибку.
- Повторный отчёт заменяет свой report.txt, вход не повреждается; TOTAL;5 отвергнута.
