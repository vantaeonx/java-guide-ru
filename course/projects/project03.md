# Мини-проект 03. Бронирование рабочего пространства

После главы 11. Модель объектов, конструкторы, private и операции с инвариантами.

## Договор приложения

Создай Room с неизменяемым id, capacity>0 и private reserved от 0 до capacity. Методы reserve(int), cancel(int), available(), id(). Аргументы операций неотрицательны; нехватка мест или отмена больше reserved -> IllegalArgumentException без изменения. BookingDesk хранит защитную копию массива Room, ищет по id и выполняет операции; id комнат уникальны и ненулевые, null-комнаты запрещены. Для неизвестного id возвращай false без изменения, для найденного корректная операция возвращает true. Комнаты изменяемы; явно документируй, что копия массива не клонирует Room. Main демонстрирует сценарий на фиксированных данных, консольный парсер не требуется. Методы стола: boolean reserve(String id,int n) и boolean cancel(String id,int n).

## Исходные данные

```java
String[] ids = {"A", "B"};
int[] capacities = {4, 2};
```

## Этапы

1. Опиши инвариант Room и проверь конструктор.
2. Реализуй reserve/cancel: сначала проверки, затем изменение.
3. Добавь BookingDesk с поиском и проверкой уникальности id.
4. Сделай проверочный main с успешными операциями и ожидаемыми отказами.

## Критерии готовности

- Для A: reserve(3) -> свободно 1; cancel(1) -> свободно 2.
- Попытка reserve(3) после этого отвергнута, свободно всё ещё 2.
- Операции A не меняют B; неизвестный X -> false.
- Изменение исходного массива после создания не заменяет комнаты стола; null и повтор id в конструкторе запрещены.
