# 05. Условия и полная система случаев

## Ветка выбирает действие

`if` выполняет блок, когда boolean-условие истинно. `else` выполняется при ложном условии. В цепочке if / else if / else выбирается первая подходящая ветка, остальные не проверяются. Несколько отдельных if независимы: могут выполниться несколько блоков. Выбор между ними определяется тем, должны ли результаты исключать друг друга.

Полезно начать с таблицы случаев: какие входы допустимы, как они разделяются и что делать на границе. Если температура ровно равна порогу, программа должна отнести её к конкретной категории. Слова «больше», «не меньше» и «от ... до ... включительно» имеют разные переводы в операторы.

## Порядок проверок

Сначала можно отвергать недопустимые входы, затем классифицировать допустимые. Внутри цепочки более узкие случаи должны предшествовать более широким, если иначе они станут недостижимыми. Например, проверка «значение положительное» поглотит «значение больше ста», если поставлена первой и обе находятся в одной цепочке.

Проверка диапазона состоит из двух сравнений. Логика «вне диапазона» использует ||, а «внутри» - &&. Отрицание составного условия можно получить по законам де Моргана: отрицание A && B равносильно !A || !B. Это инструмент проверки, а не обязанность писать максимально сложную формулу.

```java
public class Example05 {
    public static void main(String[] args) {
        int battery = 37;
        String state;
        if (battery < 0 || battery > 100) {
            state = "Некорректно";
        } else if (battery < 20) {
            state = "Зарядить";
        } else {
            state = "Можно ехать";
        }
        System.out.println(state);
    }
}
```

```output
Можно ехать
```

Все ветки присваивают state, поэтому после цепочки значение определено. Если убрать else, компилятор может обнаружить путь без присваивания. Эта проверка полезнее случайного начального значения, которое маскировало бы неполную систему случаев.

## Switch и условное выражение

Switch удобен для выбора по дискретному значению: команде, номеру, enum. В Java 17 можно использовать стрелочную форму `case ... -> ...`; она не проваливается в следующую ветку. В старой форме с двоеточием часто нужен break. В курсе простые переключения записаны стрелочной формой; это синтаксис Java 17, не preview.

Switch-выражение должно дать результат для всех возможных случаев; switch-инструкция выбирает действие. Для произвольных числовых диапазонов обычно яснее if. В Java 17 switch по String не принимает null: проверяй такой вход заранее, если null разрешён.

Тернарное выражение `condition ? a : b` возвращает одно из двух значений. Оно удобно для короткого выбора подписи. Не вкладывай несколько таких выражений вместо читаемой системы веток. Ветка, которую не выбрали, не вычисляется.

## Строки и осторожность со скобками

Для сравнения текстового содержимого используй equals. Оператор == проверяет совпадение ссылочных значений; некоторые литералы могут давать true из-за интернирования, создавая ложную уверенность в ошибочном подходе. Запись `"go".equals(command)` безопасна даже при command == null, если именно такое поведение нужно договору.

Пустая инструкция после if, например лишняя точка с запятой, делает условный блок пустым. Следующая строка выполняется независимо. Всегда ставь фигурные скобки: добавление второй инструкции позже не должно незаметно изменить её условность.

## Границы и самопроверка

Для каждого порога проверь значение ниже, ровно на пороге и выше. Для двух независимых признаков составь четыре комбинации true/false. Если два условия перекрываются, запиши, кто имеет приоритет. Если не покрывают все входы, явно определи запасную ветку или ошибку.

Объясни различие двух if и if/else if. Покажи, почему `x != 1 || x != 2` истинно для любого int. Перед практикой составь таблицу решений на бумаге; код должен стать переводом этой таблицы.
