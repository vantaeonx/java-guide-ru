# 20. Современные модели и сборка законченного приложения

## Enum вместо произвольной строки

Когда набор состояний закрыт, enum ограничивает его: `NEW`, `ACTIVE`, `DONE`. Опечатка в имени становится ошибкой компиляции, а не странной веткой во время запуска. Enum может иметь поля и методы. Внешний текст нужно явно преобразовать в допустимое состояние; valueOf требует точного имени и бросает исключение для неизвестного.

Не выбирай enum, если набор определяется пользователем и растёт из файла без пересборки. Представление должно соответствовать источнику правил. Переходы между состояниями тоже нужно проверять: наличие трёх значений не означает, что любой переход допустим.

## Record как модель значения

Record в Java 17 - краткая форма класса для данных с компонентами. Он получает конструктор, методы доступа по именам компонентов, equals, hashCode и toString. Record final и не предназначен для наследования от другого класса. Можно добавить проверку в компактный конструктор и обычные методы.

Неизменяемость record поверхностна. Компонент List может ссылаться на изменяемый список; проверка конструктора и List.copyOf помогают защитить структуру. Record хорош для координат или результата вычисления, но не заменяет любую модель с жизненным циклом и управляемым изменением.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Example20 {
    enum Priority { LOW, HIGH }

    record Ticket(String title, Priority priority) {
        Ticket {
            if (title == null || title.isBlank() || priority == null) {
                throw new IllegalArgumentException("invalid ticket");
            }
        }
    }

    public static void main(String[] args) {
        List<Ticket> tickets = new ArrayList<>(List.of(
                new Ticket("Мост", Priority.HIGH),
                new Ticket("Арка", Priority.LOW)));
        tickets.sort(Comparator.comparing(Ticket::title));
        tickets.forEach(ticket -> System.out.println(ticket.title()));
    }
}
```

```output
Арка
Мост
```

## Lambda и ссылка на метод

Функциональный интерфейс имеет один абстрактный метод. Lambda задаёт его реализацию короткой записью. В forEach параметр ticket получает очередной элемент; тело выполняется для каждого. `Ticket::title` - ссылка на метод, здесь предоставляющая ключ сравнения. Сначала умей записать то же поведение обычным классом с интерфейсом, тогда краткая форма не будет магией.

Локальная переменная, используемая lambda, должна быть final или effectively final: не переназначаться после инициализации. Это не делает все захваченные объекты неизменяемыми. Побочные эффекты в цепочках вычислений ухудшают проверяемость; ясный цикл часто лучше сложной цепочки. Потоки Stream, параллелизм и конкурентные коллекции требуют отдельного изучения.

## Минимальное реальное приложение

У законченного консольного приложения есть сценарии, формат входа, модель, команды, сохранение, обработка отказов и способ запуска. README должен объяснять действие пользователя, а не устройство каждой внутренней переменной. Данные для демонстрации должны быть безопасными и воспроизводимыми.

Упаковать выбранную точку входа можно в JAR с манифестом main-класса. JAR - контейнер классов и ресурсов, а не отдельная JVM. Для запуска нужен совместимый runtime. `--release 17` ограничивает синтаксис, доступные API и целевой байткод при компиляции современным JDK. Это сильнее, чем одно `-source 17`, но запуск тестов именно на Java 17 остаётся отдельной проверкой.

Для примера упражнение Ex001 после сборки можно упаковать так:

```bash
jar --create --file build/demo.jar \
    --main-class ru.vantaeonx.javaguide.ch01.Ex001 \
    -C build/run/Ex001 .
java -jar build/demo.jar
```

Сначала собери выбранный файл через tools/run.sh. В JAR попадут его классы из отдельного каталога, включая вложенные. Для другого упражнения замени имя и пакет согласованно. Заготовка без твоего вывода и после упаковки останется пустой.

Maven в проекте задаёт структуру и release; shell-скрипты позволяют учиться без установки Maven. Позднее инструмент зависимостей понадобится для библиотек и модов. Не нужно внедрять веб-фреймворк до понимания границ модели и ввода-вывода.

## Путь к Minecraft

Переносимые знания здесь - классы, интерфейсы, коллекции, события как вызовы, состояние и чтение документации API. Требования к Java у конкретной версии игры и загрузчика нужно проверять по их официальной документации перед созданием мода. Нельзя считать установленный JDK 25 автоматически подходящим для любой версии Minecraft.

Следующий учебный шаг - выбрать одну версию игры и один загрузчик, собрать минимальный пример по их документации и добавить одно наблюдаемое поведение. Не начинай с огромной системы или нескольких несовместимых версий. Курс даёт языковой фундамент; API игры, многопоточность и публикация мода требуют собственной практики.

Перед итоговым проектом объясни, где приложение хранит истину о состоянии, кто проверяет данные и кто сообщает об отказе. Если модель можно проверить без консоли и диска, ты уже построил полезную границу ответственности.
