# 09. Методы и передача значений

## Метод задаёт отдельный контракт

Метод объединяет действие под именем. Его объявление задаёт модификаторы, возвращаемый тип, имя, параметры и тело. Параметры - локальные переменные вызова; аргументы - значения, переданные при вызове. Метод с результатом обязан вернуть значение подходящего типа на каждом обычном пути выполнения. Void-метод результата не возвращает; печать на экран не заменяет return.

Полезный контракт отвечает на вопросы: какие входы разрешены, что возвращается, что изменяется снаружи, какие ошибки возможны. Например, метод площади не должен молча печатать случайное предупреждение и возвращать ноль, если вызывающий код ожидает результат или исключение.

## Java всегда передаёт по значению

При вызове копируется значение аргумента. Для int это число. Для массива или объекта это ссылочное значение, а не сам объект. Поэтому метод может через копию ссылки изменить общий объект, но не может переназначить переменную вызывающего кода. Это не «передача по ссылке» в смысле изменения чужой переменной.

```java
public class Example09 {
    static int perimeter(int width, int height) {
        return 2 * (width + height);
    }

    static void repaint(int[] cells) {
        cells[0] = 8;
        cells = new int[] {1, 1};
    }

    public static void main(String[] args) {
        int[] board = {2, 3};
        repaint(board);
        System.out.println(board[0]);
        int border = perimeter(4, 6);
        System.out.println(border);
    }
}
```

```output
8
20
```

Первое присваивание в repaint меняет общий массив. Второе меняет только локальную ссылку cells. После возврата board по-прежнему указывает на первоначальный массив. Нарисуй два ссылочных значения в момент входа в метод, затем отдельный новый массив после переназначения.

## Декомпозиция вместо длинного main

Main удобно оставить координатором: прочитать данные, вызвать вычисление, показать результат. Чистый вычислительный метод возвращает результат без чтения терминала и записи файла. Его можно проверить несколькими вызовами и использовать в другом интерфейсе.

Не дроби код по случайному числу строк. Выделяй действия с понятным именем и устойчивым договором. Если метод и читает пользователя, и считает, и сохраняет, тестировать отдельное вычисление трудно. Если параметров слишком много, возможно, не хватает объекта предметной области.

## Static, перегрузка и область видимости

Static-метод принадлежит классу. Он не имеет this и не может напрямую читать состояние конкретного объекта. Пока работа идёт с данными аргументов, static-метод естественен. Позже методы объектов будут использовать поля собственного экземпляра.

Перегрузка - несколько методов с одним именем и разными списками типов параметров. Возвращаемого типа недостаточно для перегрузки. Выбор перегрузки происходит при компиляции по доступным типам аргументов; это отличается от переопределения в наследовании.

Локальные переменные разных вызовов независимы. Рекурсия создаёт новый вызов метода, который должен приближаться к базовому случаю. Для длинных последовательностей обычный цикл часто проще и не расходует стек на каждый шаг. В курсе рекурсия факультативна.

## Ошибки и проверка понимания

Если метод только печатает, его результат нельзя использовать как число. Если часть веток не возвращает значение, сначала уточни контракт для этих случаев. Если метод неожиданно меняет массив, подпиши побочный эффект или верни копию. Не маскируй недописанный метод правдоподобным нулём: в заготовках методы могут явно бросать UnsupportedOperationException, пока не реализованы.

Перед практикой опиши один метод в трёх предложениях: вход, результат, изменение состояния. Объясни, какие значения копируются при передаче массива. Приведи пример, когда печать результата должна оставаться вне вычислительного метода.
