# 04. Ввод как договор о формате данных

## Почему ввод сложнее готовой переменной

При присваивании `int amount = 6` данные уже проверил компилятор. В терминале пользователь передаёт текст: пустую строку, лишние пробелы, буквы, число вне диапазона. Программа должна понимать формат, преобразовать его и решить, что делать при нарушении договора. Пока обработка исключений не изучена, в первых заданиях формат гарантируется условием. В главе 14 вернёмся к ошибочному вводу.

Scanner оборачивает источник и читает из него данные. `System.in` представляет стандартный ввод. Импорт `java.util.Scanner` позволяет использовать короткое имя Scanner. Импорт не загружает стороннюю библиотеку: это класс стандартной платформы.

## Токен и строка - разные единицы

`next()` читает следующий токен, обычно до пробельного разделителя. `nextInt()` читает токен и преобразует его в int. `nextLine()` читает остаток текущей строки до её конца и потребляет разделитель строки. После nextInt перевод строки часто ещё находится во входе. Немедленный nextLine тогда вернёт оставшуюся часть, часто пустую.

Есть два понятных протокола. Первый: читать все поля по строкам и явно преобразовывать числовые строки через Integer.parseInt. Второй: читать токены, а при переходе к построчному формату осознанно потреблять остаток строки. Не добавляй лишний nextLine везде «на всякий случай»: он может проглотить полезные данные.

```java
import java.util.Scanner;

public class Example04 {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        String city = input.nextLine();
        int platforms = Integer.parseInt(input.nextLine().trim());
        System.out.println(city + ": " + (platforms + 1));
    }
}
```

```input
Новая пристань
4
```

```output
Новая пристань: 5
```

Здесь город может содержать пробелы, а число занимает следующую строку. `trim()` удаляет края числовой строки, не меняя city. Пример не объявляет, что любое содержимое терминала допустимо: пустая или нечисловая вторая строка вызовет ошибку преобразования. Контракт ввода нужно писать в условии, а позже проверять в коде.

## Локаль и вывод

Scanner.nextDouble зависит от локали: разделителем дробной части может оказаться запятая или точка. Чтобы учебные проверки воспроизводились, договоримся о точке и используем `input.useLocale(Locale.ROOT)` для токенового чтения double. Double.parseDouble также принимает обычную десятичную запись с точкой. Не смешивай формат, который обещан пользователю, с настройками машины.

Для форматированного вывода `printf(Locale.ROOT, "%.2f%n", value)` задаёт две цифры после точки и платформенный перевод строки. Это представление результата, а не изменение его точности. Не округляй каждое промежуточное измерение без причины: ошибку округления можно накопить.

## Источник данных и время жизни

Используй один Scanner над System.in на запуск программы. Несколько обёрток могут буферизовать один источник и мешать друг другу. Закрытие Scanner закрывает связанный источник, поэтому общий ввод не следует закрывать внутри вспомогательного метода, пока приложение ещё читает. Для короткого main окончание процесса освобождает ввод; для файловой обёртки нужно управляемое закрытие, которое изучим отдельно.

В заготовках на ввод оставлен комментарий о точном протоколе. Ты пишешь чтение самостоятельно. Если используются фиксированные исходные данные, задание прямо говорит, что ввод не нужен. Это два разных варианта упражнения, а не повод незаметно заменить один другим.

## Ошибки и проверка понимания

Если «пропало имя», восстанови последовательность токенов и переводов строк. Если число не принимается, проверь разделитель и диапазон int. Если программа ждёт, возможно, ей ещё нужна строка по контракту; курс не требует сразу читать весь ввод одной командой.

Перед практикой нарисуй вход как символы с отметками `\n`. Покажи, какую часть забирает каждый вызов Scanner. Объясни различие между синтаксически верным целым и допустимым числом предметов. Вторую проверку программа выполняет отдельно.
