# 10. Класс, объект и состояние экземпляра

## От набора переменных к модели

Класс описывает допустимую структуру объектов: их поля и методы. Объект - конкретный экземпляр с собственным состоянием. Два объекта одного класса могут иметь разные значения полей. Если приложению нужны десять посылок, не создавай переменные weight1, weight2 и так далее: создай десять объектов одной модели.

Поля живут вместе с объектом и доступны его методам по правилам доступа. Локальные переменные принадлежат выполнению метода. Поля получают значения по умолчанию: 0 для целых, false для boolean, null для ссылок. Это не доказывает, что объект с таким состоянием допустим по смыслу; конструкторы исправят эту проблему в следующей главе.

## Identity и общая ссылка

Выражение new создаёт объект и возвращает ссылочное значение. Несколько переменных могут указывать на один объект. Изменение через одну ссылку видно через другую. Две независимо созданные вещи с одинаковыми полями не обязаны быть равны по ==: это разные объекты.

```java
public class Example10 {
    static class Beacon {
        int level;

        void raise() {
            level++;
        }
    }

    public static void main(String[] args) {
        Beacon north = new Beacon();
        Beacon alias = north;
        Beacon south = new Beacon();
        alias.raise();
        System.out.println(north.level);
        System.out.println(south.level);
        System.out.println(north == alias);
        System.out.println(north == south);
    }
}
```

```output
1
0
true
false
```

Вложенный static-класс в примере позволяет сохранить всё в одном файле. Он не означает, что level общее для всех объектов. Ключевое слово static у вложенного класса лишь убирает необходимость иметь экземпляр внешнего Example10.

## Поля и методы static

Поле экземпляра имеется у каждого объекта отдельно. Static-поле принадлежит классу и разделяется всеми экземплярами этого класса в обычной загрузке приложения. Счётчик всех созданных объектов может быть static; имя конкретной посылки - нет. Если сделать всё static, независимые объекты начнут мешать друг другу.

Метод экземпляра вызывается относительно объекта и имеет this - ссылку на текущий экземпляр. При совпадении имени параметра и поля `this.name = name` различает их. Присваивание `name = name` меняет параметр на него самого и оставляет поле прежним.

## Поведение и ответственность

Объект полезен, когда он объединяет данные с поведением и правилами их изменения. Метод `consume(amount)` может контролировать остаток. Внешний код, который напрямую меняет поле, способен обойти это правило. Поэтому открытые поля в примере - промежуточная учебная модель, а не рекомендация для готового приложения.

Не каждый существующий предмет требует класса. Модель выбирается под задачу: для маршрута могут быть нужны координаты остановки, но не её цвет. Сначала выпиши операции, затем данные, необходимые для их поддержки. Избыточная иерархия классов усложняет понимание без пользы.

## Жизненный цикл и память

Локальная ссылка может исчезнуть после выхода из метода, но объект остаётся доступным, если до него ведёт другая живая ссылка. Объект, недостижимый для работающей программы, может быть освобождён сборщиком мусора. Момент этого освобождения не следует использовать для закрытия файлов или записи важных данных.

Null не создаёт пустой экземпляр. Перед вызовом метода нужно либо гарантировать существование объекта контрактом, либо обработать отсутствие. Лучше уточнить, допускается ли отсутствие, чем расставлять проверки null повсюду без модели.

## Ошибки и самопроверка

Частые причины: перепутанные static и поля экземпляра; ожидание автоматической глубокой копии; вызов метода через null; чтение начального 0 как законного состояния; забытый this. Для диагностики нарисуй объекты отдельно от переменных.

Перед практикой объясни, сколько объектов создают два new и одно присваивание ссылки. Покажи, какие поля принадлежат каждому объекту. Расскажи, почему сборщик мусора не заменяет дисциплину работы с внешними ресурсами.
