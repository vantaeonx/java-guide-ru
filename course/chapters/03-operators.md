# 03. Выражения, арифметика и логика

## Тип результата определяется выражением

Выражение вычисляет значение. Операция `a + b` не обязана иметь тип переменной, в которую её результат будет записан. В `double x = 7 / 2` деление выполняется над двумя int, даёт целое 3, и только затем оно превращается в 3.0. Для дробного деления хотя бы один операнд должен стать дробным до операции.

У целого деления дробная часть отбрасывается к нулю. Остаток `%` согласован с этим делением: для целых выполняется `a == (a / b) * b + a % b`, если b не равен нулю. Знак ненулевого остатка совпадает со знаком делимого. Это важно для отрицательных координат: остаток Java не всегда совпадает с математическим модулем; для циклических индексов существует Math.floorMod.

## Порядок операций и побочные эффекты

Умножение и деление имеют более высокий приоритет, чем сложение. Скобки показывают замысел даже там, где технически не нужны. Операнды Java вычисляет слева направо; приоритет задаёт группировку, а не разрешение переставлять вызовы произвольно.

`x++` возвращает старое значение и затем увеличивает x. `++x` сначала увеличивает. Когда увеличение нужно само по себе, отдельная инструкция `x++` яснее сложного выражения. Избегай нескольких изменений одной переменной в одном выражении: такая запись тренирует угадывание, а не проектирование.

Оператор `+` соединяет строки, если операция уже стала строковой. Поэтому `"Сумма: " + 2 + 3` последовательно приклеит две цифры. Группировка числовой части скобками меняет результат. Печать - тоже место, где нужно учитывать тип промежуточного значения.

```java
public class Example03 {
    public static void main(String[] args) {
        int minutes = 95;
        System.out.println(minutes / 60 + ":" + minutes % 60);
        System.out.println(9 / 4);
        System.out.println(9 / 4.0);
        System.out.println(-9 % 4);
        boolean safe = minutes > 0 && 120 / minutes >= 1;
        System.out.println(safe);
    }
}
```

```output
1:35
2
2.25
-1
true
```

## Переполнение и точность

Целые примитивы имеют конечный диапазон. Обычное сложение int при переполнении не выдаёт исключение: результат оборачивается в пределах 32 бит. Если два int перемножаются до присваивания long, переполнение уже произошло. Расширь один операнд заранее либо используй подходящую проверяемую операцию Math.addExact или Math.multiplyExact.

Double представляет многие десятичные дроби приближённо. Результат 0.1 + 0.2 не обязан быть в точности 0.3. Форматирование до двух знаков меняет показ пользователю, но не внутреннее значение. Допуск для сравнения выбирают из смысла измерения, а не один магический порог для любой задачи.

Деление целого на ноль вызывает ArithmeticException. Дробное деление использует правила IEEE 754 и может дать Infinity или NaN. Для начинающего приложения лучше заранее определить допустимость знаменателя, чем ждать удобного поведения типа.

## Булева логика

Сравнения `==`, `!=`, `<`, `<=`, `>` и `>=` возвращают boolean. `&&` требует истинности обеих частей, `||` - хотя бы одной, `!` отрицает значение. Короткое замыкание означает, что правая часть && не вычисляется при false слева, а правая часть || - при true слева. Проверку безопасности ставят перед потенциально опасным выражением.

`&` и `|` с boolean вычисляют обе стороны. Для целых они означают побитовые операции. Не заменяй ими && и || случайно. Присваивание `=` и сравнение `==` выполняют разные действия; равенство ссылок не равно равенству содержимого строк.

## Типичные ошибки и самопроверка

Если результат выглядит слишком маленьким, проверь целое деление и типы до операции. Если огромное произведение стало отрицательным, оцени диапазон промежуточного выражения. Если условие «между» записано как `0 < x < 10`, разбей его на два boolean-сравнения с &&.

Объясни, почему `(double) (a / b)` и `((double) a) / b` различаются. Назови ситуацию, где порядок двух частей && защищает программу. Перед практикой вручную вычисли промежуточные типы в строковом сложении.
