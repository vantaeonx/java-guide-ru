# 08. Строки: содержание, Unicode и неизменяемость

## String - объект с неизменяемым содержимым

Строка представляет последовательность UTF-16-кодовых единиц. String неизменяем: методы вроде trim, replace и toUpperCase возвращают результат, не переписывая исходное содержимое. Присваивание `text = text.trim()` меняет ссылку text на результат. Если забыть присваивание, исходная переменная останется прежней.

Строка `""` существует, имеет нулевую длину и не равна null. Null означает отсутствие объекта; вызов метода через null вызывает NullPointerException. Пробельная строка не пуста: length учитывает пробелы. Метод isBlank проверяет пустоту или пробельное содержимое по правилам API.

## Равенство и индексы

Equals сравнивает содержимое String. Оператор == сравнивает ссылочные значения. JVM может переиспользовать строковые литералы; поэтому == иногда даёт ожидаемый ответ случайно. Не выводи правило языка из единственного удачного опыта с литералами.

`charAt(i)` возвращает кодовую единицу, `substring(begin, end)` берёт полуинтервал: begin включён, end исключён. Длина результата равна end - begin. Для пустого диапазона begin == end результат пустой. Индекс end может равняться length, но charAt(length) недопустим.

```java
import java.util.Locale;

public class Example08 {
    public static void main(String[] args) {
        String label = "  Dock-12  ";
        String clean = label.trim().toLowerCase(Locale.ROOT);
        System.out.println(clean);
        System.out.println(label.length());
        System.out.println(clean.substring(0, 4));
        String face = "\uD83D\uDE00";
        System.out.println(face.length());
        System.out.println(face.codePointCount(0, face.length()));
    }
}
```

```output
dock-12
11
dock
2
1
```

## Что значит «символ»

В литерале \uD83D\uDE00 явно записана суррогатная пара одного emoji. Emoji в примере занимает две UTF-16-единицы, хотя кодовая точка одна. Некоторые видимые символы вообще состоят из нескольких кодовых точек, например буква и комбинируемое ударение. Поэтому length не гарантирует количество видимых символов. В большинстве начальных задач алфавит явно ограничен ASCII или русскими буквами без комбинируемых последовательностей. Если задача разрешает любой Unicode, договор другой.

Для обхода кодовых точек можно использовать codePointAt и Character.charCount, либо поток codePoints после знакомства с потоковыми API. Не переворачивай произвольный Unicode-текст простым обменом char, не понимая суррогатных пар. Сложная пользовательская сегментация текста выходит за рамки обычного char-цикла.

## Поиск, разбиение и сборка

IndexOf возвращает -1 при отсутствии. Перед substring на найденной позиции нужно проверить это значение. StartsWith и endsWith выражают конкретный вопрос яснее ручного извлечения кусочков.

Split принимает регулярное выражение. Точка означает любой символ, а не буквальную точку; для буквальной точки нужен экранированный шаблон. В `split(";", -1)` отрицательный limit сохраняет пустые поля в конце. Это важно для файлового формата: `name;` содержит второе пустое поле, а не одно поле.

При многократном добавлении текста в цикле удобен StringBuilder: изменяемый накопитель с append, после которого вызывают toString. Это отделяет процесс сборки от неизменяемого итогового значения. Не используй один общий builder для независимых сообщений без очистки.

## Ошибки и самопроверка

Не применяй trim к полю, если пробелы по договору значимы. Не используй системную локаль для идентификаторов: правила регистра могут зависеть от языка. Locale.ROOT полезна для машинных ключей, но не решает все задачи естественного языка.

Перед практикой объясни разницу null, пустой строки и строки из пробелов. Назови пределы charAt. Покажи на примере, почему `text.replace(...)` без присваивания не меняет text. Уточняй в условии, что именно считается символом.
