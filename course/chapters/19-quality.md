# 19. Отладка, проверки и слои приложения

## Успех запуска ещё не доказательство

Программа может завершиться без исключения и посчитать неверную стоимость. Проверка должна сравнить наблюдаемое поведение с условием. Один пример подтверждает только один случай. Для диапазона нужны границы, для коллекции - пустота, один элемент и повторы, для отказа - вход, который обязан быть отклонён.

Сначала разделяй наблюдение и гипотезу. «При входе 0 получено -1» - наблюдение. «Проблема в начальном максимуме» - гипотеза. Измени один фактор или проверь промежуточное значение, чтобы отличить её от других объяснений.

## Отладчик и минимальный воспроизводимый пример

В IDEA поставь breakpoint на исполняемой строке. Debug остановит выполнение перед ней. Step Over выполняет текущую операцию без входа внутрь метода, Step Into входит в вызываемый метод, Resume продолжает до следующей остановки. Наблюдай значения и стек вызовов. Некоторые выражения в Evaluate Expression способны менять состояние; не вызывай случайные методы только ради просмотра.

Для цикла найди первую итерацию, где инвариант перестаёт выполняться. Для объекта проследи создание и последний метод изменения. Если проблема исчезает на маленьком входе, увеличивай его по одному элементу. Это быстрее, чем перечитывать весь файл без конкретного вопроса.

```java
public class Example19 {
    static int clamp(int value, int low, int high) {
        if (low > high) {
            throw new IllegalArgumentException("invalid bounds");
        }
        return Math.max(low, Math.min(value, high));
    }

    static void check(boolean condition, String name) {
        if (!condition) {
            throw new AssertionError(name);
        }
    }

    public static void main(String[] args) {
        check(clamp(-3, 0, 9) == 0, "below");
        check(clamp(4, 0, 9) == 4, "inside");
        check(clamp(12, 0, 9) == 9, "above");
        System.out.println("3 проверки пройдены");
    }
}
```

```output
3 проверки пройдены
```

Это простой проверочный стенд без библиотек. AssertionError здесь явно создаётся проверяющим методом. Он отличается от ключевого слова assert, которое по умолчанию может быть выключено и требует `-ea`. Не используй отключаемый assert для проверки пользовательского ввода.

## Полезные тесты

Тест должен проверять договор, а не повторять реализацию той же формулой с теми же ошибками. Для маленького примера ожидаемый результат можно вывести вручную. Для сортировки полезны свойства: элементы не потеряны, порядок не убывает, повторная сортировка не меняет результат. Для перевода в формат и обратно полезен round-trip, но он не доказывает соответствие внешнему формату, если обе стороны одинаково ошибаются.

Отказы тоже проверяются: неверный аргумент должен быть отвергнут, состояние после отказа должно сохранять инвариант. Не засчитывай любой пойманный Exception как нужный отказ: проверь конкретный тип и точку, которую тестировал.

## Разделение обязанностей

Небольшое приложение удобно делить на три части. Модель содержит данные и правила. Сервис выполняет сценарий над моделью. Адаптеры читают консоль, печатают и работают с файлом. В начале это могут быть методы или вложенные классы; количество файлов не является целью.

Если вычисление зависит от терминала, файла и текущего времени одновременно, его трудно воспроизвести. Передавай входные данные и зависимости явно. Для накопителя сообщения можно подменить вывод реализацией интерфейса. Для счётчика дней можно передать дату вместо обращения к реальным часам внутри каждой функции.

## Регрессия и границы автоматизации

После исправления добавь минимальный случай, который ловил ошибку. Затем выполни связанные проверки. Компиляция всех стартовых файлов проверяет каркас курса, но не правильность ещё не написанных решений. Автоматическая сверка условий и данных обнаруживает рассинхронизацию, но не заменяет педагогическое чтение текста.

Перед практикой запиши ожидаемое поведение до реализации. Для одного случая определи обычный вход, границу и отказ. Объясни, что именно доказывает каждая проверка и какое поведение остаётся непроверенным.
