# 11. Конструкторы, инкапсуляция и инварианты

## Объект должен начинать жизнь корректным

Конструктор выполняется при создании экземпляра. Его имя совпадает с именем класса; возвращаемый тип не пишется, даже void. Если конструкторы не объявлены, компилятор предоставляет конструктор без аргументов. Если объявлен хотя бы один, автоматический вариант без аргументов больше не добавляется.

Конструктор нужен, чтобы задать обязательные данные и проверить правила. Инвариант объекта - утверждение, которое должно быть истинно после завершения конструктора и каждого публичного изменения. Для измерителя объёма это может быть `0 <= amount && amount <= capacity`. Если объём недопустим, создание объекта должно завершиться отказом, а не скрытой подменой данных.

## Private и единая точка проверки

Private-поле недоступно произвольному внешнему коду. Публичные методы дают контролируемые операции. Это инкапсуляция: устройство может меняться, пока договор методов остаётся прежним. Геттеры и сеттеры не являются обязательной парой для каждого поля. Метод `reserve` лучше выражает смысл, чем безусловный `setReserved`.

```java
public class Example11 {
    static final class Charge {
        private final int capacity;
        private int amount;

        Charge(int capacity) {
            if (capacity <= 0) {
                throw new IllegalArgumentException("capacity must be positive");
            }
            this.capacity = capacity;
        }

        void add(int units) {
            if (units < 0 || units > capacity - amount) {
                throw new IllegalArgumentException("invalid charge");
            }
            amount += units;
        }

        int amount() {
            return amount;
        }
    }

    public static void main(String[] args) {
        Charge charge = new Charge(10);
        charge.add(4);
        System.out.println(charge.amount());
    }
}
```

```output
4
```

Смысл throw будет подробно разобран в главе 14; здесь достаточно понимать, что неверная операция прерывается до изменения поля. Проверка через `capacity - amount` избегает переполнения суммы при допустимом инварианте. Все проверки выполняются до изменения состояния.

## Перегрузка и делегирование конструкторов

Можно предложить несколько способов создания с разными параметрами. Вызов `this(...)` делегирует другому конструктору того же класса и в Java 17 должен быть первой инструкцией. Так одна основная проверка обслуживает все варианты создания. Дублирование проверки в нескольких местах со временем приводит к несовпадающим правилам.

This обозначает текущий экземпляр, а не родительский класс. Конструктор не является обычным методом и не вызывается как `object.ClassName()`. Присваивание полям после new не заменяет конструктор, если объект между этими действиями уже может попасть в чужой код.

## Неизменяемые модели и defensive copy

Неизменяемый объект после создания не меняет наблюдаемое состояние. Обычно этому помогают final-класс, private final-поля, проверка входов и отсутствие методов изменения. Но final-ссылка на массив запрещает только переназначение ссылки, а содержимое массива остаётся изменяемым.

Если сохранить переданный массив напрямую, вызывающий код сможет поменять внутреннее состояние после проверки. Если вернуть внутренний массив из геттера, доступ откроется снова. Защитная копия на входе и выходе разрывает этот канал. Для массива изменяемых объектов одной поверхностной копии может быть недостаточно; нужно продумать владение элементами.

## Доступ и пакеты

Public доступен извне, private ограничен классом и связанными вложенными контекстами, отсутствие модификатора даёт доступ в пакете. Protected связан с пакетом и наследованием; его тонкости рассмотрим в следующей главе. Пакет не является защитой от недоверенного кода, но помогает организовать внутренний API приложения.

## Ошибки и самопроверка

Если сеттер принимает всё, private само по себе не защищает инвариант. Если ошибка возникает после изменения половины полей, объект может остаться противоречивым. Проверяй все условия до записи либо вычисляй новое состояние отдельно.

Перед практикой сформулируй инвариант будущего класса. Перечисли все пути изменения. Объясни, почему final-массив не равен неизменяемому массиву и почему скрывать поле полезнее, чем просто переименовать его.
