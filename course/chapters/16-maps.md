# 16. Map, равенство и хеширование

## Ключ ведёт к одному значению

Map хранит пары ключ-значение. Это не список пар с дубликатами ключей: один ключ связан не более чем с одним значением. Put для уже существующего ключа заменяет значение и возвращает прежнее. Значения разных ключей могут совпадать.

HashMap не обещает порядок обхода. LinkedHashMap может сохранять порядок вставки, TreeMap - порядок ключей по сравнению. Если в условии требуется детерминированный отчёт, выбери подходящую структуру или отсортируй ключи перед выводом.

Get возвращает null при отсутствии ключа, но HashMap может также хранить null как значение. Для различения нужен containsKey либо договор, запрещающий null-значения. GetOrDefault подставляет значение при отсутствии записи, но не заменяет существующее значение null.

```java
import java.util.LinkedHashMap;
import java.util.Map;

public class Example16 {
    public static void main(String[] args) {
        String[] tools = {"пила", "молоток", "пила"};
        Map<String, Integer> counts = new LinkedHashMap<>();
        for (String tool : tools) {
            int old = counts.getOrDefault(tool, 0);
            counts.put(tool, old + 1);
        }
        for (Map.Entry<String, Integer> entry : counts.entrySet()) {
            System.out.println(entry.getKey() + ": " + entry.getValue());
        }
    }
}
```

```output
пила: 2
молоток: 1
```

GetOrDefault не добавляет запись сам. Изменение происходит в put. Обход entrySet даёт ключ и значение вместе. В примере порядок первого появления сохраняется выбранной реализацией, а не свойством любого Map.

## Что считает равными HashMap и HashSet

Object.equals по умолчанию сравнивает идентичность. Для собственного класса-значения часто нужно сравнивать значимые поля. Equals должен быть рефлексивным, симметричным, транзитивным, согласованным при неизменности значимых данных и возвращать false для null.

HashCode связан с equals: если два объекта равны, их хеш-коды обязаны совпадать. Обратное неверно: разные объекты могут иметь одинаковый хеш. Коллизия не является ошибкой; структура дополнительно проверяет равенство. Переопределяй equals и hashCode вместе и по одним значимым данным.

Зачем нужны оба? Хеш помогает быстро выбрать область поиска, equals определяет соответствие внутри неё. Если равные объекты имеют разные хеши, структура может искать не там и не находить запись, которая по смыслу существует.

## Опасность изменяемого ключа

Если после вставки поменять поля ключа, участвующие в hashCode, объект останется размещён по прежнему хешу, а новый поиск будет использовать новое значение. Даже поиск тем же объектом может перестать работать. Для ключей подходят неизменяемые значения: String, enum, корректно устроенные собственные типы, некоторые record.

Не путай изменение значения Map с изменением ключа. Остаток товара можно менять, если идентификатор товара остаётся стабильным. Если изменился идентификатор, это операция удаления старой связи и создания новой, а не случайное редактирование поля.

## Сравнение и сортированные структуры

TreeMap использует сравнение ключей; договор сравнения должен быть согласован с предполагаемым равенством. Результат 0 означает эквивалентный ключ для сортированной структуры. Если сравнить людей только по возрасту, два разных человека одинакового возраста могут слиться в одну запись. Для сортировки отчёта и для определения уникальности иногда нужны разные договоры.

Для Integer сравнения не вычитай значения ради результата comparator: вычитание может переполниться. Integer.compare выражает сравнение без этой ошибки. Comparator будет практически использован в главе о lambda.

## Ошибки и самопроверка

Проверь повторный put, отсутствующий ключ, пустую карту и несколько ключей с одинаковым значением. Не полагайся на порядок HashMap и не проверяй его текстовый вывод как обязательный.

Перед практикой объясни, почему одинаковый hashCode не доказывает equals. Нарисуй последствия изменения ключа. Укажи, какая часть модели должна оставаться стабильной в телефонном справочнике и в реестре складских позиций.
