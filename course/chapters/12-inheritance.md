# 12. Наследование и полиморфизм

## Когда один тип является разновидностью другого

Наследование `extends` описывает отношение типов. Объект подкласса может использоваться там, где ожидается базовый класс. Это обещание поведения, а не только способ скопировать поля и методы. Если подкласс нарушает договор базового типа, программа с общей ссылкой становится непредсказуемой для клиента.

Класс Java имеет один непосредственный базовый класс. Если extends не написан, обычный класс наследует Object. Конструкторы не наследуются. В Java 17 конструктор подкласса сначала вызывает this или super; если ничего не написано, вставляется super() при его доступности. Наличие только конструктора родителя с аргументом требует явного вызова.

## Статический тип и реальный объект

Статический тип ссылки задаёт доступные операции при компиляции. Реальный класс объекта определяет, какое переопределение метода экземпляра будет выполнено. Именно это позволяет одному циклу работать с разными разновидностями объектов без цепочек instanceof.

```java
public class Example12 {
    static abstract class Route {
        abstract int minutes();
    }

    static class Walk extends Route {
        @Override
        int minutes() {
            return 18;
        }
    }

    static class Tram extends Route {
        @Override
        int minutes() {
            return 7;
        }
    }

    public static void main(String[] args) {
        Route[] routes = {new Walk(), new Tram()};
        for (Route route : routes) {
            System.out.println(route.minutes());
        }
    }
}
```

```output
18
7
```

В цикле переменная имеет тип Route, но не создаёт отдельный объект Route. Она получает ссылку на Walk, затем Tram. Abstract-класс нельзя создать напрямую; abstract-метод задаёт обязательную операцию без реализации в базовом классе.

## Override не равен overload

Переопределение сохраняет совместимую сигнатуру метода экземпляра. Аннотация Override просит компилятор проверить намерение и ловит опечатки. Нельзя сузить видимость переопределяемого метода. Возвращаемый ссылочный тип может быть уточнён совместимым подтипом. Ограничения checked-исключений важны после главы 14.

Перегрузка выбирает между разными списками параметров при компиляции. Static-методы скрываются, а не переопределяются с динамическим выбором как методы экземпляра. Поля тоже не участвуют в таком полиморфном выборе. Поэтому не используй одинаковые имена полей родителя и потомка как замену переопределению поведения.

## Super и состояние родителя

Super позволяет обратиться к реализации базового класса или его конструктору. Private-поле родителя нельзя напрямую читать из подкласса; для работы с состоянием предназначены методы базового класса. Protected не означает «открыто всем потомкам в любой ситуации»: за пределами пакета действуют дополнительные правила доступа через наследование. Сначала предпочитай private и небольшой ясный API.

Не вызывай переопределяемый метод из конструктора родителя без крайней необходимости. Он может попасть в код подкласса раньше, чем подкласс завершил инициализацию собственных полей. Объект ещё строится, а динамический выбор уже работает.

## Композиция и безопасные границы

Наследование удобно, когда связь «является» устойчива и договор действительно общий. Для отношения «использует» лучше поле другого объекта: это композиция. Сервис доставки использует принтер, но не является принтером. Изменение стратегии тогда не требует перестройки родословной классов.

Приведение базовой ссылки к подклассу не превращает объект. Оно лишь утверждает, что объект уже подходящего типа. Неверное утверждение вызывает ClassCastException. Если приходится постоянно проверять конкретные подклассы, возможно, общему договору недостаёт операции.

## Ошибки и самопроверка

Перед практикой укажи статический и фактический тип каждого объекта примера. Объясни, кто выбирает перегрузку и кто выбирает переопределение. Придумай нарушение договора базового типа: например, подкласс внезапно запрещает вход, разрешённый родителем. Поведение клиента должно оставаться осмысленным при подстановке любой законной разновидности.
