# 15. List и Set: порядок, дубликаты и изменение

## Почему массива бывает недостаточно

Размер массива фиксирован. Когда число элементов меняется, коллекция берёт управление хранением на себя. List описывает последовательность с индексами и дубликатами. Set описывает множество без дубликатов по договору равенства элементов. Выбирай структуру по смыслу, а не по привычке использовать один тип всегда.

`List<String>` означает список строк. Параметр типа позволяет компилятору проверять добавление и чтение; полный механизм generics будет разобран в главе 17. Здесь достаточно знать: это не имя отдельного класса ListString. Для int в коллекциях используется Integer; boxing и unboxing связывают примитив и объектную обёртку.

## Интерфейс и реализация

`List<String> names = new ArrayList<>()` разделяет роль и реализацию. Клиенту нужен договор List, хранение обеспечивает ArrayList. ArrayList удобно читать по индексу и добавлять в конец; вставка в начале сдвигает элементы. Не считай любую операцию одинаково дешёвой.

HashSet не обещает порядок обхода. LinkedHashSet сохраняет порядок вставки, TreeSet поддерживает сортированный порядок по сравнению. Случайный устойчивый порядок HashSet в одном запуске не является договором API.

```java
import java.util.ArrayList;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;

public class Example15 {
    public static void main(String[] args) {
        List<String> stops = new ArrayList<>();
        stops.add("порт");
        stops.add("парк");
        stops.add("порт");
        Set<String> unique = new LinkedHashSet<>(stops);
        System.out.println(stops.size());
        System.out.println(unique);
        List<Integer> levels = new ArrayList<>(List.of(4, 8, 4));
        levels.remove(Integer.valueOf(4));
        System.out.println(levels);
    }
}
```

```output
3
[порт, парк]
[8, 4]
```

Последний remove удаляет первое равное значение 4. Вызов remove(1) выбрал бы перегрузку с индексом. Это особенно важно для List<Integer>: выбор перегрузки зависит от типа аргумента.

## Изменяемость не определяется одной ссылкой

List.of создаёт неизменяемую по структуре коллекцию и не допускает null. Попытка add вызывает UnsupportedOperationException. `new ArrayList<>(List.of(...))` создаёт изменяемую копию структуры. Объекты внутри копии могут остаться общими.

Arrays.asList возвращает список фиксированного размера, связанный с исходным массивом объектов: set возможен, add/remove размера - нет. Не называй все эти варианты просто «обычным списком». List.copyOf помогает получить неизменяемую структуру, но не глубокую копию изменяемых элементов.

Unboxing null в int вызывает NullPointerException. Обёртки могут быть null, примитив int - нет. Сравнивай значение Integer через equals или осознанное распаковывание при гарантированном ненулевом значении; == может зависеть от переиспользования объектов.

## Удаление во время обхода

Удаление из ArrayList через список внутри enhanced for может нарушить итератор и вызвать ConcurrentModificationException. Это возможно даже в одном потоке: название не означает обязательную многопоточность. Используй Iterator.remove, removeIf после изучения predicate или отдельный список результата. Не полагайся на исключение как гарантированный детектор всех неправильных изменений.

Для поиска повторов множество удобно: результат add сообщает, появился ли новый элемент. Для сохранения всех вхождений нужен список, а не множество. Для подсчёта частот потребуется Map следующей главы.

## Ошибки и самопроверка

Проверь пустую коллекцию, один элемент и повтор. Уточни, должен ли сохраняться порядок. Перед практикой объясни различие размера и максимального индекса. Покажи, почему final-ссылка не запрещает add в ArrayList, а List.of запрещает его без final. Выбери структуру для журнала событий и для набора уникальных разрешений.
