# 13. Интерфейсы и композиция

## Договор без общей родословной

Интерфейс описывает набор операций, которые обещает тип. Класс объявляет implements и реализует эти операции. Разные классы могут поддерживать один интерфейс, не наследуя общую реализацию. Класс может реализовать несколько интерфейсов, хотя базовый класс у него один.

Обычный абстрактный метод интерфейса публичен. Реализация должна быть public, даже если рядом все классы находятся в одном пакете. Поля интерфейса являются public static final-константами; это не поля будущего экземпляра. Для состояния реализации используй класс.

## Клиент зависит от нужной возможности

Если форматтеру нужен способ отправить строку, ему не обязательно знать, отправляется ли она в консоль или накапливается в памяти. Передача зависимости через конструктор позволяет выбрать реализацию извне. Это делает устройство приложения видимым и даёт возможность проверять клиент без реального внешнего действия.

```java
public class Example13 {
    interface Output {
        void write(String message);
    }

    static class ConsoleOutput implements Output {
        @Override
        public void write(String message) {
            System.out.println(message);
        }
    }

    static class Greeting {
        private final Output output;

        Greeting(Output output) {
            this.output = output;
        }

        void welcome(String place) {
            output.write("Добро пожаловать: " + place);
        }
    }

    public static void main(String[] args) {
        Greeting greeting = new Greeting(new ConsoleOutput());
        greeting.welcome("мастерская");
    }
}
```

```output
Добро пожаловать: мастерская
```

Greeting содержит Output: это композиция. В примере зависимость считается ненулевой по контракту. В готовой публичной модели стоит проверить это в конструкторе. Для теста вместо ConsoleOutput можно передать накопитель сообщений; вычисление приветствия останется прежним.

## Выбор размеров интерфейса

Интерфейс должен описывать цель клиента, а не все возможности огромного сервиса. Если клиент только читает, не заставляй его зависеть от удаления и записи. Небольшой договор проще реализовать и проверить. Но отдельный интерфейс для каждого метода без задачи тоже создаёт лишние имена.

Default-метод интерфейса может содержать реализацию, обычно через другие операции договора. Static-метод вызывают через имя интерфейса. Если два интерфейса дают несовместимые default-реализации, класс должен явно разрешить конфликт. Не используй default как скрытое место для состояния: экземплярных полей интерфейса нет.

## Стратегия как заменяемое поведение

Стратегия - объект, который реализует один способ вычисления. Например, разные правила маршрутизации поддерживают одну операцию выбора стоимости. Клиент хранит ссылку интерфейсного типа и вызывает её. Выбор новой стратегии не меняет код клиента.

Это особенно полезно на границе внешнего мира: часы, хранилище, генератор случайных чисел, уведомления. Для проверки можно передать предсказуемую реализацию. Не нужно подключать сложный фреймворк, чтобы освоить принцип: обычного конструктора достаточно.

## Интерфейс, абстрактный класс и окончательная модель

Интерфейс подходит для роли и возможного множества реализаций. Абстрактный класс полезен для действительно общего состояния и базовой реализации родственников. Final-класс запрещает наследование, когда расширение не предусмотрено договором. Эти средства отвечают на разные вопросы; ни одно не является универсально «более объектным».

## Ошибки и самопроверка

Если реализация компилируется только после удаления Override, возможно, метод вовсе не реализует договор: проверь имя, параметры и public. Если клиент создаёт конкретную зависимость внутри каждого вызова, подменить её в проверке трудно. Если интерфейс содержит слишком много несвязанных операций, опиши несколько разных клиентов и их реальные потребности.

Перед практикой нарисуй два объекта и связь «содержит». Объясни, почему ConsoleOutput можно заменить, не меняя Greeting. Назови различие между переиспользованием реализации через наследование и переиспользованием поведения через поле.
